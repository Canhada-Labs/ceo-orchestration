# contamination-personal-path-allowlist.txt — waivers for RULE 2 of
# .claude/scripts/check_contamination.py (the `personal-path` rule).
#
# ONE row per file, `<path> | sha256:<64 hex> | <reason>`. No globs, no
# directory prefixes, no generated baselines: every shape that waives a
# file nobody named is the shape the rule exists to remove. A row is a
# DECISION and the decision is written down; adding one belongs in the
# same change as the file it waives.
#
# THE DIGEST IS PART OF THE DECISION. A row waives the file only while
# its bytes still hash to the recorded sha256 — the bytes a human read
# when they wrote the reason. Edit the file and the waiver LAPSES on
# purpose: the gate names the file, `--emit-personal-path-rows` prints
# the new row with the new digest, and a human re-reads and re-approves.
# A row can no longer waive a file forever, which is what let a second
# leak land silently in an already-waived file.
#
# A row waives the whole file AT THAT DIGEST, and it never waives a
# PATH: a file whose own name carries a home directory has to be
# RENAMED — a row naming one is refused at parse time.
#
# NOTHING IS EXEMPT BY NAME OR BY SUFFIX. Not `OWNER-*.sh`, not `*.asc`,
# not any extension: every in-scope tracked path is read and matched the
# same way, symlinks included (a link is judged by its target string).
# Three versions of this rule shipped a name-shaped skip and the
# pair-rail found each one -- the last of them let a tracked symlink
# named `OWNER-*.sh` carry a home path straight through the gate that
# failed the same target under any other name.
#
# A SIGNED SENTINEL IS NOT SPECIAL. `approved.md` / `*-approved.md` used
# to be waived by a RULE that asked four questions of content -- a
# sibling `.asc`, an armoured signature body, an `Approved-By`
# fingerprint granted by a `signer-fingerprint:` row here, and
# not-a-symlink. Every answer is transplantable by anyone who can write a
# file, so it was a waiver earned by the NAME `*-approved.md` in a
# content-shaped costume. It waived nothing on this tree and it is GONE.
# A frozen signed artifact that really does carry a home path takes a row
# like anything else -- and because the signature freezes the bytes, that
# row's digest cannot lapse behind anyone's back.
#
# UPGRADING FROM v4.0: delete any `signer-fingerprint: <40 hex>` line.
# The directive no longer exists, so the parser reads it as a MALFORMED
# row and the gate goes red naming it -- deliberately, rather than
# ignoring a line an operator believes is still granting something.
# Verifying a real signature is
# `PLAN-186-FOLLOWUP-sentinel-gpg-verification.md`; when it lands it is a
# SECOND way to waive, earned by a signature this gate checks.
#
# THIS FILE MUST BE TRACKED BY GIT to waive anything. The gate
# confirms that with `git ls-files` before it parses a single row:
# an untracked copy -- or one removed from the index with
# `git rm --cached` -- is read as EMPTY, so no row waives.
# Trackedness is what makes a waiver a diff somebody reviewed rather
# than a file somebody touched. It is NOT a promise that this file is
# readable in `git diff`: a staged `.gitattributes`, a diff driver
# configured as binary, or `core.bigFileThreshold` can each make git
# print one `Binary files ... differ` line where the rows are. Four
# rail rounds tried to defend the readability of this file and each
# cure was defeated by a NAME one round later, which is the one kind of
# decision this rule refuses to make.
#
# So the gate no longer asks git anything about how this file renders.
# On EVERY run it PRINTS the rows it HONOURED --
# `<path> | sha256:<64 hex> | <reason>`, one line each, in path order,
# uncapped, with a sha256 over the set. A waiver that grants a file is
# therefore visible in the log of the run that granted it, whatever a
# diff shows and whether or not anybody opens one.
#
# THE REASON IS PART OF THE GRAMMAR. After NFKC it must carry at least
# EIGHT characters from [A-Za-z0-9], and every character must be
# printable. A one-word reason (`frozen`), an empty one, or one built
# from invisible or filler codepoints is MALFORMED by row number and
# waives nothing. Eight is a word somebody typed: it is what separates a
# written decision from a character that satisfies a predicate.
#
# A row that matches no file is STALE: reported, never fatal (a row waives one
# path, so a row matching nothing waives nothing). `--fail-on-stale` makes it
# fatal for a maintainer who wants the rot flagged.
#
# ADOPTERS: this file DOES NOT YET TRAVEL WITH A FRESH INSTALL -- the
# installer copies `*.sh`, `*.py` and `*.yaml` out of `.claude/scripts/` and
# nothing copies a `.txt`, so a new checkout gets the rule and an EMPTY
# allowlist (fail-closed: your own findings are reported, never waived). The
# installer fix is canonical and travels in a signed ceremony. If you DID
# receive this file -- by upgrading, or by copying it in -- nearly every row
# below names a framework plan artifact your checkout does not have. Those
# are the stale rows. Delete them and record YOUR tree instead:
#     python3 .claude/scripts/check_contamination.py --emit-personal-path-rows
# then write a reason on each row (the emitted placeholder is refused).
#
# WHAT THESE ROWS ARE, honestly: GRANDFATHER entries. Every path below carried
# an absolute home directory before the rule existed. `CEREMONY:` and `RAIL:`
# rows are frozen evidence that must not be rewritten. `RESIDUAL:` rows are
# NOT ceremony material — they are real findings with no cure in this change
# (rewriting another wave's plan artifact is out of scope); they are named
# file:line in the pack EVIDENCE and are the follow-up work.
