NEW FINDINGS (annex)

P1. .claude/hooks/_lib/bash_indirect_guard.py:154 (quote tracking in _command_substitutions), reached from :229-231 (the scan of an unquoted here-doc body, source_comments=False) and :234 (only shell/eval consumers get their body scanned as code). An apostrophe in an unquoted here-doc body hides any later $(...) or backquote from the scan.
- Cause: in a here-doc body, quotes are literal and bash runs every command substitution no matter what quotes surround it. _command_substitutions still treats the body as shell source and opens a single-quote state on the first "'". After that, the $( test at :156 (quote != "'") and the backquote test at :180 never fire.
- Scenario: cat <<EOF > notes.txt / it's $(rm -rf ~) / EOF. The rm runs in bash.
  - _extract_heredocs matches the unquoted delimiter and calls _command_substitutions on the body "it's $(rm -rf ~)\n".
  - The apostrophe sets quote="'", so the $( is skipped and the call returns None.
  - The consumer is "cat", not a shell, so :234 does not queue the body for a source scan, and the body is cut from the command text.
  - The rest, "cat <<EOF > notes.txt", is clean, so scan() returns None.
  - The base rail also allows this command. _split_subcommands does not split on newlines, the single chunk fails shlex, and _recheck_whole_command skips a chunk that is still unbalanced (normalization.py:589-594).
- Any ordinary English contraction ("don't", "it's") earlier in the body is enough to trigger this.
- Not a regression: v1.4.3-rc.1 allowed this too. It is a gap in the new guard, and it contradicts CHANGELOG [1.4.4] line 84, which says the scan covers rm -rf reached "inside sh -c, eval or a here-doc". It is the same class as declared rc item claude-p16 P1-3 but has a different root cause, so fixing P1-3 does not fix it.
- Minimal fix: when source_comments is False (here-doc data), do not track quote state in _command_substitutions; honor only backslash escapes before $ and backquote. Add allow and block tests for: cat <<EOF / it's $(rm -rf ~) / EOF.
