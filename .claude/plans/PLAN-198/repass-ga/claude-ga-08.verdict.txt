1. P2 (new). Symlinks in the term rule fail closed on checkouts the personal-path rule already handles.
   - Where: .claude/scripts/_contamination_inventory.py:76-81, reached through .claude/hooks/_lib/_contamination/term_scan.py:38-47.
   - Defect: for index mode 120000, Rule 1 calls os.readlink() and turns any OSError into RuleOneInputError.
   - Scenario A: under core.symlinks=false (the Git for Windows default), git writes a tracked link as a regular file. readlink fails with EINVAL, so any repo with a tracked symlink anywhere gets "FATAL ... cannot read a tracked symlink payload" and rc 2.
   - Scenario B: a tracked link that is absent from the worktree (sparse checkout, or a local deletion) also gives rc 2 (ENOENT). An absent regular file is skipped (:87-88).
   - Contrast: the base followed the link and passed. Rule 2's _personal_path_read_nofollow handles both cases (it reads the file, or returns None when it is absent). The facade census (check_contamination.py:455-457) says "tracked but absent is still not unreadable", but test_fu144_tracked_but_absent_is_still_not_unreadable covers only a regular file.
   - Impact: limited. The adopter template runs on ubuntu-latest (validate.yml.template:34), and the failure is in the closed direction of a gate, not a hook.
   - Fix: when readlink fails with EINVAL on a regular file, read that file's bytes as the payload. Return None on ENOENT. Add both cases to the fu144 tests.
