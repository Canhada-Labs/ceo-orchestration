P2 FOLLOW-UPS

1. P2 — .claude/scripts/check_contamination.py:130-135 (fail-open on a permission fault).
- Failure: os.path.lexists() returns False on EACCES. On Python 3.9 the old Path.is_file() re-raised EACCES, because only ENOENT, ENOTDIR, EBADF and ELOOP are ignored. So when the CI user cannot search the scanned repo's scripts/ directory, every private term is now dropped in silence.
- The comment "Only real ABSENCE means no private terms" overstates what the code does.
- Why P2, not P1: git does not record directory modes, so a PR cannot cause this. A PR that wants the same effect can simply delete the terms file, which is absent-by-design. And in this repository, Rule 1 still returns rc 2 through other non-allowlisted tracked files under scripts/.
- Fix: call os.lstat() and treat only ENOENT and ENOTDIR as absence; let any other error propagate.

2. P2 — .claude/scripts/_contamination_inventory.py:76-81 and :89 (symlinks).
- core.symlinks=false: for mode 120000, _blob only calls os.readlink(). On a checkout with core.symlinks=false (the Git for Windows default), git writes the link as a regular file, readlink raises EINVAL, and every non-allowlisted tracked symlink makes Rule 1 return rc 2 on every run. The base code scanned that file with read_bytes().
- Missing links: a deleted or sparse-excluded tracked symlink also returns rc 2, while a missing regular file is skipped.
- EMLINK: the ELOOP fallback does not handle EMLINK, which FreeBSD returns.
- Why P2, not P1: it fails closed, and adopter CI runs on ubuntu-latest.
- Fix: reuse Rule 2's _personal_path_read_nofollow classification. On EINVAL, read the regular file; on ENOENT or ENOTDIR, return None; treat EMLINK like ELOOP.
