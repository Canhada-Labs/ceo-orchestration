NEW FINDINGS (annex)

P1 — After the bounded-exit export, the spool drains at most 100 events per non-hook process exit, while the work of each drain grows with the backlog.
- Where: .claude/hooks/_python-hook.sh:410, with _lib/_spool_writer_parts/lifecycle.py:346-358, _lib/_audit_emit_parts/writer.py:585-591, _lib/_spool_writer_parts/prepare.py:83-122 (should_drain) and _lib/_spool_writer_parts/drain.py (phase 4 K_MAX cap; phase 5 at :489-505).
- Why hook processes stop draining:
  - Inside a hook process, the only drain left is the opportunistic one at writer.py:590-591.
  - should_drain() runs right after spool_append() has refreshed the spool file's mtime, so its 100 ms staleness test is false.
  - Only its 100-line test can fire. A hook process that emits fewer than 100 events never drains, and with the export it no longer drains at exit either.
- Where the events go:
  - Hook events stay in per-PID spool files.
  - They are collected only when a process started outside the shim imports audit_emit and exits: its atexit forced drain at lifecycle.py:352.
- What each of those drains costs:
  - It appends at most K_MAX = 100 entries.
  - Phases 2-3 still rename, read, parse and sort every pending spool file.
  - Phase 5 rewrites, fsyncs and renames every file it did not fully consume, including files with no consumed line (drain.py:489-505).
  - All of this happens under the canonical lock.
- Failure scenario: in a hook-heavy session, hooks write several events per tool call, more than 100 per non-hook exit.
  - The HMAC-chained canonical log falls further behind.
  - Readers of the log see stale data (audit-query, /ceo-boot, and the spawn file-overlap rail already annexed by claude-p12/p19).
  - `state/` gains one file per hook process.
  - Every later non-hook script exit pays a cost proportional to the backlog.
- What the release declares: condition 8 and Known-open say the cure is partial and that collection is not proven. They do not say that the remaining drain capacity is 100 events per non-hook exit while the work per drain grows with the backlog.
- Basis: derived from the code. Not measured.
- Minimal fix:
  - Ship the drainer with no deadline that ADR-055-AMEND-4 §4.2 names as a precondition. It must run outside the shim, for example in boot or nightly, and loop drain_now(force=True) until no spool remains.
  - In phase 5, leave a .draining file with no consumed line untouched instead of rewriting it.
  - Until then, state this throughput limit in Known-open.
