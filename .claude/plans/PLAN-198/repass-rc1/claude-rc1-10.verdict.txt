P1 — .claude/hooks/_lib/_pair_rail_parts/part_01.py:477-486, with CHANGELOG.md:191.
Problem: when the host's target triple is absent from the manifest, the code runs _apply_currency_policy before any payload is resolved or hashed.
- With no override, currency_path is the PATH launcher. The result is status=compatible, path=launcher and sha256="". _resolve_codex_bin then returns the launcher and it gets executed. Nothing was hashed, and the native payload was never resolved.
- The manifest pins only aarch64-apple-darwin. So this route applies on every other host (Linux x86_64/arm64, Intel macOS, Windows). Before this delta it was the documented fail-CLOSED result triple_missing ("unverifiable must not silently degrade").
- With CEO_PAIR_RAIL_CODEX_BIN set, the override gets no is_file() check on this route. A missing override path that has any @openai/codex package.json above it newer than 0.160.0 returns compatible. The subprocess then raises FileNotFoundError, which becomes CodexUnavailable and an advisory: fail-OPEN. This inverts "inexistente = BLOQUEIA" (the line 520 contract).
- CHANGELOG [1.4.4] line 191 says "The payload's sha256 is still computed and recorded". That is false on this route.
Who is affected: maintainer and reviewer checkouts only. Installs do not receive .claude/governance/, so for them the manifest is absent and the pin fails open as before. The kit refuses this route for the re-pass. Condition 9 declares only the broad version-only trust, not this route.
Minimal fix: in the entry-is-None branch, first resolve the real payload. For an override, require is_file(). For the launcher, use the vendor/<triple> path. Hash it and record sha256 and path, then apply the currency policy. Otherwise keep triple_missing. Then correct CHANGELOG line 191 to name this route.
