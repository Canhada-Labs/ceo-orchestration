NEW FINDINGS (annex)

P1 — the fail direction of the canonical-edit hook when one of its components is missing is inverted, and it differs from caller to caller.
Where:
- .claude/hooks/check_canonical_edit.py:616-640. On ImportError from the component bind, _COMPONENT_IMPORT_IS_INTEGRITY_FAILURE is set and the fallback main() prints a block for every event without reading it.
- .claude/hooks/_lib/canonical_edit/entry.py:126-133 repeats the same branch.
What it contradicts:
- .claude/hooks/_python-hook.sh:332-335: "a missing file, an ImportError, a timeout must never block the user session".
- The facade's own docstring, check_canonical_edit.py:36-40: "Any internal exception → allow".
- Rule 2 of this cut. The CHANGELOG and the conditions declare nothing about this; ADR-202:56-59 and PLAN-197:45 only mention a "separate import-integrity work".
Failure scenario:
- In a partial install or upgrade, or with a component file deleted, every Edit/Write/MultiEdit call is blocked for the whole session. So is every mcp__.* tool call, read-only MCP tools included, because the shipped matcher is templates/settings/settings.base.json:116.
- The same fault class goes the other way elsewhere:
  - A non-ImportError fault while importing or binding (a SyntaxError in a component, for example) gives allow-all.
  - A failure to import guards.py alone (check_canonical_edit.py:118-127) silently sets _CANONICAL_GUARDS=[]. That disarms the gate with no breadcrumb. The fallback branch also assigns stale names (_SKILL_CONTENT_RE, _SKILL_LOADED_RE, _VALID_BLOCKED_TOOLS) and leaves _MCP_WRITE_PATH_KEYS undefined, so mcp__ events crash with a NameError and emit nothing.
  - The MCP Layer-B library (_lib/mcp/canonical_guard.py:244-248 and :654-660) documents fail-CLOSED on import failure. Now `import check_canonical_edit` succeeds, `_is_canonical` is missing, the AttributeError is caught and returns False, and canonical writes are allowed.
Minimal fix:
- Choose one posture and declare it. Either declare the ImportError fail-closed as an exception like ADR-186 in the CHANGELOG's Known-open and narrow it to events whose path classifies as canonical (guards.py does not depend on the package __init__), or move to allow plus stderr and an audit breadcrumb, as the shim's contract says.
- In both cases: the guards fallback should set _COMPONENT_IMPORT_ERROR; and mcp/canonical_guard._lazy_init should return _REASON_IMPORT_FAILURE when `getattr(_cce, "_COMPONENT_IMPORT_ERROR", None)` is set or `_is_canonical` is not callable.
Why P1 and not P0: it only happens on a broken tree, the block reason names the cause, and Bash stays available to reinstall.

P2 follow-ups

1. P2 — .claude/hooks/_lib/effective_config.py:238 together with :712-716. The non-greedy `\((.*?)\)` in _WORKING_SET_RE stops at the ")" of the tuple's first comment (ADR-149-model-id-allowlist.md:82, "(base ADR-149 Decision; ...)"). It captures no id, so the parser falls back to every quoted id anywhere in the ADR. It never uses "the legacy floor block" that the docstring promises. Today the result equals the working set only by coincidence. A future ADR line that quotes a non-family claude id would silently join the tamper allowlist. This affects the framework repo only: install.sh ships only .claude/adr/README.md. Fix: anchor the closing paren as `^\)` with re.M, or strip comments before matching.
