NEW FINDINGS (annex)
P1: the latency profiler is not fully isolated from the live audit log.
- Where: .claude/hooks/_lib/_profile_opus_parts/latency.py:102-127 and :198-199. The isolation claim it contradicts is at .claude/hooks/_lib/_profile_opus_parts/hook_latency_docs.py:87.
- What the code does: run_hook_latency copies the whole os.environ, removes only CEO_LEARNING_OBSERVE, CEO_SOTA_DISABLE, CEO_TOOL_LIFECYCLE, CEO_ANTI_OVERHEAD, CLAUDE_SESSION_ID and CLAUDE_PROJECT_DIR_NATIVE, and then sets HOME and CEO_AUDIT_LOG_DIR for each corpus entry.
- Why that is not enough: the writer gives CEO_AUDIT_LOG_PATH priority over CEO_AUDIT_LOG_DIR (_audit_emit_parts/writer.py:187-208), and so do audit_hmac._audit_dir_from_env (audit_hmac.py:189) and spool_writer. The profiler leaves these variables in place: CEO_AUDIT_LOG_PATH, CEO_AUDIT_LOG_LOCK, CEO_AUDIT_LOG_ERR, CEO_AUDIT_KEY_PATH, CEO_AUDIT_LAST_HMAC_PATH, CEO_AUDIT_CHAIN_LENGTH_PATH and CEO_PROJECT_STATE_DIR.
- Failure scenario: a maintainer or adopter with CEO_AUDIT_LOG_PATH exported runs "profile-opus-4-7.py --hook-latency" (N=200 by default). The five corpus entries make roughly 1,400 hook runs, counting the seed runs. Every check_agent_spawn, check_anti_ceo_overhead and check_output_secrets event from those runs is appended to the LIVE audit log and HMAC chain under session "profile_latency".
- Relation to the base re-pass: this is the same defect the v1.4.3-rc.1 re-pass ranked P1 in diagnose-output-hook.py. Condition 3(a) fixed it only there, by removing _CHILD_LOCATION_CARRIERS (diagnose-output-hook.py:27-34). That script even imports this profiler module, but the profiler's own gate was not fixed.
- Minimal fix: in latency.py, remove the same list of variables from base_env as diagnose-output-hook.py:27-34 (or as the list in test_isolation.py), before HOME and CEO_AUDIT_LOG_DIR are set per entry. Also set CEO_PROJECT_STATE_DIR per entry, and add a test that runs the profiler with CEO_AUDIT_LOG_PATH set and checks that the real log stays the same.

P2 FOLLOW-UPS
1. Honesty: two docstrings describe the old snapshot write path.
- Where: .claude/hooks/_lib/_precompact_parts/snapshot_core.py:335-340, and the docstring of check_precompact_continuity.py:57-63.
- Both say the snapshot is handed to store.set as a str so that the store's redactor runs. The code at snapshot_core.py:424-426 now redacts each field first and passes BYTES. It passes a str only when _lib.redact fails to import.
- Secrets are still redacted. One side effect: on the bytes path, state_store's "redacted" column records 0 even when a field was redacted.
- Fix: update both docstrings to describe the field-level redaction and the bytes write.
2. The PreCompact facade loses its module docstring.
- Where: .claude/hooks/_lib/_precompact_parts/__init__.py:16.
- exec() of each part file stores that part's own docstring as the facade's __doc__, so check_precompact_continuity.__doc__ ends up as runtime.py's one-line docstring instead of the 85-line contract. audit_log.py:315/328 saves and restores __doc__ for exactly this reason; this facade does not.
- I found no production code that reads it. Fix: save __doc__ before install and restore it after.
3. Project-root resolution can pick a nested directory.
- Where: .claude/hooks/_lib/_precompact_parts/snapshot_core.py:53.
- _resolve_project_root takes the nearest ancestor that has a .claude/ directory before it looks at CLAUDE_PROJECT_DIR. When the session's working directory is inside a nested .claude/ tree (a monorepo package, a fixture), the plan lookup and the ceremony glob move there. So does the hysteresis-marker write, when CEO_CONTEXT_PROGRESS_FLOOR_TOKENS is set and the sidecar identity check passes.
- The hook fails soft and the marker write is opt-in. Fix: prefer CLAUDE_PROJECT_DIR when the working directory is inside it, and apply the same rule in the PostCompact reader.
4. Stale help text: .claude/hooks/_lib/_reality_ledger_parts/dispatch.py:136 says "Default: all 5" for --detector, but DETECTOR_REGISTRY has 6 detectors (estimate_drift is the sixth). Cosmetic; probably carried over unchanged.
5. A second, unused action registry (cross-reference to another payload).
- _audit_emit_parts/actions.py defines a second _KNOWN_ACTIONS (actions_core | actions_extended). Nothing imports it, and it is not in the install list of audit_emit.py:415-452.
- The writer checks against the literal set in the facade (writer.py:558 against audit_emit.py:45). The fallback that _read_known_actions adds in this payload (audit_actions.py) can only resolve a _KNOWN_ACTIONS that a module in the install list exports, so it is inert today.
- Risk: two sources of truth. An action added only to actions_core.py or actions_extended.py would be dropped silently. Fix: delete actions.py and its two data modules, or make the facade take _KNOWN_ACTIONS from it.
