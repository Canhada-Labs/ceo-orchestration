NEW FINDINGS (annex)

P1 — .claude/hooks/check_canonical_edit.py:616-640 (mirrored in _lib/canonical_edit/entry.py:126-134). The fail direction on an infrastructure fault is inverted, and this is not declared.
- What happens: when `from _lib.canonical_edit import bind` raises ImportError (a missing component file), the fallback main() prints {"decision":"block"} for every event the hook receives. That covers Edit, Write, MultiEdit, NotebookEdit and mcp__*, canonical paths or not. It does not read the event at all.
- Before this delta: an import failure in this hook crashed it (exit 1, a non-blocking error in Claude Code), so it failed open. Fail-closed was limited to confirmed-canonical paths (PLAN-045 F-01-07).
- Why it is an inversion: it contradicts the review's doctrine (infrastructure faults fail OPEN) and the hook's own docstring (check_canonical_edit.py:36-40: "Any internal exception -> allow. The hook never blocks the user on its own bug").
- Why it counts as undeclared: CHANGELOG [1.4.4] says the entry points keep their observable contracts. ADR-202:56-59 only alludes to "separate import-integrity work".
- The integrity classification is also inconsistent:
  (a) A component that raises anything other than ImportError (for example a truncated file giving a SyntaxError) falls back to allow-all (line 639).
  (b) If only guards.py fails to import, the first try at lines 118-127 silently sets _CANONICAL_GUARDS = [] with no stderr line. The package __init__ does not import guards, so bind still succeeds and _COMPONENT_IMPORT_ERROR stays None. Every path then classifies as non-canonical. That silently opens: the Edit gate, the Bash canonical-write matcher (posture_tables.py:53,160), bash_indirect_guard.py:410, the check_codex_filewrite DENY_LIST and the --is-canonical oracle. mcp__ events then crash on a NameError for _MCP_WRITE_PATH_KEYS, which fails open. Kernel hard-deny still covers the kernel paths.
- Failure scenario: an adopter's upgrade is interrupted, or _lib is pruned by hand, so check_canonical_edit.py is present but a _lib/canonical_edit/*.py file is not. Every file edit in every session is then blocked with "canonical_edit integrity failure" until the adopter reinstalls. It is recoverable through Bash, but it is the "blocking a legitimate session" class.
- Minimal fix:
  1. In the fallback main(), parse stdin and block only when a candidate path's lower-cased first segment is in _CANONICAL_PREFIXES_FOLDED; allow everything else.
  2. Move the guards import into the same integrity try, so a guards-only failure sets _COMPONENT_IMPORT_ERROR and is not silent.
  3. Or, at minimum, declare the block-all posture in CHANGELOG [1.4.4] (hooks split, plus Known-open) and correct the docstring.
