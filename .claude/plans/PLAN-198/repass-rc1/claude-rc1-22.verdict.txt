NEW FINDINGS (annex)

P1. check_canonical_edit.py:118-127 and :616-640; mirror at _lib/canonical_edit/entry.py:126-134. When the canonical_edit package is only partly present, the failure direction is undeclared, inverted against the stated doctrine, and splits two ways depending on which file is missing.
 (a) Blanket fail-CLOSED on an infrastructure fault. If any of __init__/paths/sentinels/signature_rail/session_roots/utility/decisions/entry is missing (ModuleNotFoundError, an ImportError), the fallback main() prints {"decision":"block"} for every event without reading stdin. The hook is registered on "Edit|Write|MultiEdit|mcp__.*" (templates/settings/settings.base.json:116). A partial install or interrupted upgrade therefore blocks every Edit and Write in the session, including non-canonical files, and every MCP tool call, including read-only ones.
   - This contradicts the doctrine "fail OPEN on INFRASTRUCTURE (missing file, import failure, timeout)", which the suite itself cites at tests/test_fail_open_contract.py:96-99.
   - The CHANGELOG [1.4.4] does not declare it. ADR-202 and PLAN-197:45 only mention "separate import-integrity work".
   - The sibling check_agent_spawn fails open in the same situation.
   - The fallback prints Claude-shaped JSON whatever CEO_HOOK_ADAPTER says. By entry.py:16-18's own account, that is foreign JSON on the Codex wire, so under Codex the same fault fails open instead. The direction depends on the harness.
   - test_check_canonical_edit.py:33 only exercises a canonical path.
 (b) Silent fail-OPEN when only guards.py is missing or broken. The except at :123-127 sets _CANONICAL_GUARDS = [] without touching _COMPONENT_IMPORT_ERROR. bind() still succeeds because __init__ does not import guards, so the hook runs normally with an empty guard list:
   - Every canonical edit is allowed, and no breadcrumb is written.
   - An mcp__ event dies with NameError on _MCP_WRITE_PATH_KEYS outside any try (entry.py:225-227), exits 1, and is allowed.
   - --is-canonical answers 0 with exit 0 for every path, so the Codex/Grok pre-push gates under-trigger.
   - In-process consumers (posture_tables.py:53, bash_indirect_guard.py:410, check_codex_filewrite.py:36) silently get an empty list.
 Minimal fix:
   - Route the guards import failure into the same _COMPONENT_IMPORT_ERROR state instead of [], and make _cli_is_canonical exit non-zero in that state.
   - Scope the integrity block. Read the event, block only when a candidate's first segment is in _CANONICAL_PREFIXES_FOLDED (still defined in the facade at :202), allow everything else with the stderr breadcrumb, and emit through the resolved adapter.
   - Declare the chosen posture in CHANGELOG Known-open, or as an amendment to ADR-202.
   - Add a test that a non-canonical path and a read-only mcp__ tool still pass under the missing-component condition.
 Why P1 and not P0: it needs a partial or corrupted install. Normal install and upgrade deliver the package, and the user can recover through Bash or the terminal (re-run upgrade.sh), which this hook does not gate.
