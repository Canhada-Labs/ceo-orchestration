NEW FINDINGS (annex)
P1 - .claude/scripts/ceo-restore.sh:190 (with _restore_archive.py:112-113 and ceo-backup.sh:264)
Failure scenario: ceo-backup.sh --include-plans still copies plans with `cp -pR`, which keeps symlinks as symlinks (GNU and BSD cp). tar then stores them as SYMTYPE members, and the backup exits 0 with a valid sha256 sidecar. Before staging anything, ceo-restore.sh runs `_restore_archive.py <tarball>`, which refuses any non-file, non-dir member ("refused member type"), and exits 2. The whole archive is refused, including audit/ and memory/, even without --restore-plans. Pre-1.4.4 backups whose memory/ held a link fail the same way. So the framework's own backup can produce an archive that its documented restore command (DISASTER-RECOVERY.md Scenarios B/D) refuses, and this shows up only during a disaster. Manual `tar -x` still works.
Minimal fix: in ceo-backup.sh, snapshot plans/ as regular files only, the way memory/ already is (find -type f + cp -p). Optionally, also make the restore refuse only members it would actually write, given the selected flags.

P2 FOLLOW-UPS
1. .claude/scripts/ceo-restore.sh:182-184. _physical_dest now requires the destination's parent to already exist. The old script ran `mkdir -p "$DEST"`. On a pristine home (DISASTER-RECOVERY.md Scenario D: "New laptop / new machine") where ~/.claude/projects does not exist yet, or with a deep new CEO_AUDIT_LOG_DIR, restore stops with "destination parent must be a real directory". CHANGELOG [1.4.4] does not mention this. Fix: walk up to the nearest existing ancestor, require it to be a real non-link directory, then mkdir -p; or document the step.
2. .claude/scripts/_restore_archive.py:42-47. Any name ending in "/" is refused by the parts check, so the final `rstrip("/")` can never run. If a Python tarfile keeps the trailing slash on GNU long-name directory members (GNU tar's default format, for directory paths over 100 chars), the whole archive is refused. Fix: strip a trailing slash on directories before splitting, and add a test with a GNU-format long directory name.
3. .claude/hooks/_lib/_cost_transcripts_parts/__init__.py:54-56. The class rebuild rebinds every method whose __module__ equals the part's, including the dataclass __repr__ wrapper. functools.wraps / reprlib copy __module__ onto that wrapper, and its body reads a dataclasses/reprlib global (`_thread` or `get_ident`, depending on the Python version). In the facade, repr() or str() of UsageRecord, ScanCounters, Priced and PricingResult therefore raises NameError. No production renderer stringifies them (ceo-cost.py:772 serialises the JSON-safe collect() output), but debugging, logging and test diagnostics break. Fix: rebind only functions whose __code__.co_filename is the part file, or skip __repr__.
4. Same file :35-44. The vars()-based export with a fixed list of excluded import names means any future top-level `import x` in a part puts a module into deepcopy(declarations), which raises TypeError and breaks the import. Fix: use explicit __all__, as _audit_emit_parts.install does.
5. .claude/scripts/ceo-cost-transcripts.py:208 still says "Read-only: this script writes nothing". Importing the seven parts writes bytecode under .claude/hooks/_lib/_cost_transcripts_parts/__pycache__. This is the same class of issue that condition 3(c) cured for two other read-only tools. Fix: set sys.dont_write_bytecode before the _lib imports, or reword the docstring.
