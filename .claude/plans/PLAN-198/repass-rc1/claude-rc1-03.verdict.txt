P2-1 — .claude/hooks/_lib/_audit_emit_parts/writer.py:758-761 (with :603-604 and filelock.py:144)
- Failure scenario: the F-CHAOS-1 fallback references `line` before it is assigned.
  - If the primary audit directory is unwritable and audit-log.lock does not exist yet, `FileLock.__enter__` raises OSError (EACCES) at :604. `os.open(O_CREAT)` in filelock.py:144 is the call that fails, before `line` is built at :687.
  - The except branch at :758 prints the "::warning:: ... falling back to <fallback>" banner and then calls `_write_fallback(line)`. That raises UnboundLocalError, which the outer `except` swallows.
  - The event is lost while stderr says it was diverted.
- Why tests miss it: test_audit_emit.py:1183-1211 injects the PermissionError at `Path.open` on the log, after `line` exists.
- Minimal fix: serialize the fallback line from `event` inside the except branch, as the FileLockTimeout branch already does at :751. Add a test that makes the lock path uncreatable.

P2-2 — .claude/hooks/_lib/_audit_emit_parts/writer.py:38-51, :76, :87
- Failure scenario: the fallback path `/tmp/ceo-audit-fallback-<user>.log` is predictable.
  - It is opened with `Path.open("a")`, then `os.chmod`-ed, and both calls follow symlinks.
  - On a shared host without protected_symlinks (stock macOS /private/tmp), another local user can plant that name as a symlink. When the victim's primary write fails or the lock times out, audit JSON is appended to a file the victim owns, and that file is chmod-ed to 0600.
- Minimal fix: `os.open(path, O_WRONLY|O_APPEND|O_CREAT|O_NOFOLLOW, 0o600)` plus `fchmod` on the descriptor, or a per-user 0700 directory with the same trust gate `_python-hook.sh:173-198` uses.
