P2-3. .claude/hooks/_lib/_audit_query/labeling.py:19 and :51; parsing.py, queries.py, reporting.py, reporting_health.py. These are importable modules, but they are correct only once audit-query.py rebinds them.

- labeling's own _LABEL_STORE_PATH points at .claude/hooks/_lib/_audit_query/audit-log-labels.jsonl. Its sys.path insert resolves to .claude/hooks/_lib/hooks/_lib, so audit_hmac fails to import and the fixed fallback key is used.
- Scenario: a future direct "from _lib._audit_query import labeling; labeling.cmd_label(...)" writes inside _lib, and the resulting label chain fails verification against the real key. No such caller exists today; audit-query.py is the only importer.
- Minimal fix: pass the store path and hooks directory explicitly, or add a guard that raises when the function's globals are not the facade's.
P2-4. .claude/hooks/_lib/_bash_safety_parts/decisions_cli.py:195-202, together with fact_canonical.py:147 and fact_state.py:23/38/54. The new veto_triggered emit, keyed on reason_code, reads only the final decision. When the fact gate in ENFORCE mode, or the ADR-175 citation pilot, replaces a bash_indirect_* block, the new Decision is built without reason_code. Scenario: on those paths no veto_triggered event with the indirect reason code is written; only the fact-gate or citation events are. This affects audit records only; the block decision is unchanged. Minimal fix: pass reason_code=decision.reason_code into the replacement Decision constructors.
