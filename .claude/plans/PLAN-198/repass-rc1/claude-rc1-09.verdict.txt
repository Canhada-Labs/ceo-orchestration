P2-1 (moved code changes behaviour). Files: .claude/hooks/_lib/_installer_write_safety/__init__.py:36 (_bind_class) together with syntax.py:6-10.
What is wrong: bind() copies every component class into the facade namespace with type(original)(name, original.__bases__, attrs). The bases stay the ORIGINAL classes. So the facade's Incomplete inherits from syntax.ParseError, not from the facade's ParseError, and issubclass(facade.Incomplete, facade.ParseError) is False. The rebound functions raise the facade's Incomplete, but their "except ParseError" clauses look up the facade's ParseError, so those clauses no longer catch it.
- _read_balanced and _read_dquote only ever raise Incomplete. The handlers that existed to catch them are now dead: verdicts_b.py:141 (parse_sed_script), verdicts_b.py:440 and :447 (_sole_pipeline_producer), commands.py:131 (_expansion_refs), model.py:320, :344 and :632, and operands.py:35.
- The lexer path itself still works: build_logical_lines catches the facade's Incomplete, and build_file_model catches the facade's ParseError.
How it fails: a scanned script containing  sed 's/$(/X/' f  parses fine. parse_sed_script then reaches _read_balanced, which raises Incomplete("unterminated ( expansion"). Nothing catches it, so the census exits 1 with a traceback. Before the split this produced an i-script-unparsed site. A literal "${" in a sed side fails the same way through commands.py:131. --json output and --write-baseline crash too. This contradicts the docstring of parse_sed_script, which says an unmodelled construct "yields an error, which BLOCKS". There is no broad except anywhere in the package, so the failure stays closed: validate.yml:411-414 goes red. No test covers it.
Who is affected: only the maintainer's CI census. It does not change how a hook behaves for an adopter.
Minimal fix: in bind(), clone classes in definition order and remap bases through the clones already made (bases = tuple(clones.get(b, b) for b in original.__bases__)), or leave exception classes un-cloned. Add a test that issubclass(mod.Incomplete, mod.ParseError) holds, plus a fixture with an unbalanced literal "$(" in a sed script.

P2-2 (the census misses a raw interpolation; the root is outside this payload). Files: commands.py:110-113 (_expansion_refs with honour_single_quotes=True), whose result verdicts_b.py:340 relies on.
What is wrong: the scan tracks no double-quote state. A ' inside a double-quoted raw token is read as the start of a single quote, and with no closing quote the scan returns early with no names.
How it fails:  sed "s/it's/$VAL/" f  gives names = {}. Then verdicts_b.py:340 ("if name not in names: continue") drops $VAL, and the site comes out nao-aplicavel / n0-no-interpolation, which does not block. The same early return makes model.py:612 (_token_is_expanded) miss an expansion such as "don't-$x", so no write-candidate site is created for it.
Whether this is new: I could not tell whether this predates the split.
Minimal fix: track double-quote state in _expansion_refs, and treat ' as a quote only outside double quotes.

P2-3 (honesty about records on every exit). File: .claude/scripts/night-mode.py:327-331.
What is wrong: the import of _lib._night_mode_parts runs at module level with no guard.
How it fails: if _lib or _lib/_night_mode_parts is missing or only partly installed, the script dies with a traceback (exit 1) before main(). It writes neither the night-mode-event line nor the night_mode_toggled row. The docstring promises both records on "EVERY terminating path" of on/off, and exit 2 for refusals. This is an infrastructure fault that happens before any write, so the failure stays on the safe side.
Minimal fix: wrap the import. On failure, print the _summary line and exit 2 with a diagnostic; the audit emit is best-effort anyway. Or state this exception in the docstring.
