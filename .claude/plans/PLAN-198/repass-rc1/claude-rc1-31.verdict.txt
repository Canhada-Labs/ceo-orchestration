FINDINGS
P2-1 re-pin-codex.py:496-497 and :2171-2172 — the generator mislabels the change it makes to the Codex pin range.
- Scenario:
  - The live pin's range is the unbounded floor `>=0.128.0` (.claude/governance/codex-cli-pin.txt:199; CHANGELOG 199-201).
  - The next pack generated against it gets plan_range(upper=None), which returns `>=0.128.0,<X.(Y+1).0` with widened=True.
  - run() then sets old_upper equal to new_upper.
  - The pin paragraph (:1675-1677), the sentinel (:1744-1746), the README (:1611) and the commit message (:1437-1439) all say "Upper bound widened <0.161.0 -> <0.161.0 … (widen-upper-only)".
  - Applying the pack actually adds an upper bound to an unbounded floor. That narrows the policy and reverses the version-floor route (condition 10; CHANGELOG 447-450), while the signed text calls it a widening.
  - OLD_UPPER is invented. The rehearsal, copied word for word from the newest mold, asserts `live_pin[-1] == f">={lower},<{old_up}"` (PLAN-194/codex-pin-0160/rehearse-pin-0160.sh:267), so it fails.
  - The docstring at :55-56 ("widened upper-only, and only when the version falls outside it") is no longer true.
- Why P2: the tool is maintainer-only (it refuses in installs), the failure is closed (newer CLIs get refused) and the rehearsal catches it.
- Minimal fix: when upper is None, either refuse by name ("live pin is an unbounded floor; the bounded pack grammar cannot express it") or render the change honestly ("upper bound ADDED: none -> <X", with no fabricated OLD_UPPER and widened=False). Add a plan_range test with upper=None.
