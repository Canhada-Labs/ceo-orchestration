P2 FOLLOW-UPS
1. P2 — .claude/hooks/_lib/_bash_safety_parts/posture_scan.py, decide_command, `_is_destructive = indirect_hit.reason_code != "bash_computed_canonical_target"`.
   - Problem: every indirect class except the canonical target gets destructive=True. That includes bash_indirect_limit, bash_indirect_unparseable_shell, bash_indirect_ambiguous_launcher, bash_indirect_computed_verb and bash_indirect_opaque_stdin.
   - ADR-201:80-84 tags only the trio and "its equivalent indirect forms", and says "The A-9 destructive tag is an unresolved Owner decision ... this proposal does not decide it by analogy". The code decides it.
   - Scenario: an adopter arms CEO_FACT_GATE_ENFORCE=1 in settings, or the CEO_DESTRUCTIVE_CITATION_GATE pilot. A fail-closed parse or limit denial, or a `... | bash` denial, can then be released by a verbatim transcript citation on an exact retry. The release path is audited, not silent.
   - With the default settings the verdict is unchanged. The only effect is that the shadow fact gate now also writes state and telemetry for these denials.
   - Minimal fix: map only the trio-equivalent codes to destructive=True, i.e. those returned via `_hit(code)` from _destructive(). Keep the limit, unparseable, ambiguous and heuristic codes at destructive=False until the Owner decides A-9.
2. P2 — fact_canonical.py:146-153, with the citation gate in fact_state.py.
   - Problem: when the fact gate in enforce mode reshapes a block, it builds a new Decision without reason_code. decisions_cli.py:195 then skips the veto_triggered emit that carries the bash_indirect_* class.
   - Effect: forensic detail only, and only under opt-in enforce.
   - Fix: pass reason_code=decision.reason_code into the rebuilt Decision.
3. P2 — posture_scan.py decide_command, and decisions_cli.py:171.
   - Problem: the switches are compared with `== "0"` without strip(). Sibling switches strip (_rawscan_enabled, for example), so a value like " 0" leaves the scan armed.
   - This fails safe. Fix: `str(raw).strip() == "0"`, for consistency.
4. P2 — normalization.py:4-56.
   - Problem: the library fragment carries the monolith's shebang and full module docstring as a dead string after the real docstring. That text describes "Registered in settings.json" as if this file were the hook, and its numbered list skips step 3.
   - Fix: trim it to a fragment docstring, or point it at the facade.
5. P2 — budget-summary.py and _lib/_budget_summary_parts/.
   - Dead code: cost_rollup.py's _load_normalize_model_name is overridden by the facade's copy, and the first SOURCE_CHOICES, AUDIT_BANNER and ROOT_ENV computation (budget-summary.py:341-356, with _TX_MODULE=None) is dead.
   - The part functions only work after the facade rebinds them. Calling one from a direct import raises NameError, for example _SINCE_RE in parse_since.
   - _budget_summary_parts has no __init__.py, unlike its two sibling packages.
   - audit_events.default_audit_dir keeps an unused `home` local.
   - Fix: delete the dead copies, add an __init__.py, and say in a docstring that the part modules are facade-bound only.
