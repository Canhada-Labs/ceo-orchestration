NEW FINDINGS (annex)

P1 — .claude/hooks/_lib/_installer_write_safety/__init__.py:36 (_bind_class), combined with syntax.py:10 (`class Incomplete(ParseError)`).
Defect: _bind_class clones every component class with `type(original)(name, original.__bases__, attrs)`. ParseError is cloned to ParseError' with bases (Exception,). Incomplete is cloned to Incomplete' with bases (the ORIGINAL ParseError,), not the clone. On the facade, `issubclass(Incomplete, ParseError)` is therefore False. Every bound function looks up `raise Incomplete` as Incomplete' and `except ParseError` as ParseError', so the `except ParseError` sites no longer catch Incomplete. Affected sites: commands.py:131, operands.py:35, model.py:320, 344 and 632, and verdicts_b.py:141, 440 and 447. In the old single-file module they did catch it. build_logical_lines is not affected because it catches Incomplete by name.
Concrete scenario: any scanned scripts/**/*.sh with a fully quoted dd operand, e.g. `dd if=/dev/zero "of=$dst" bs=1 count=0`. In classify_command (commands.py:516-518), canon_operand("\"of=$dst\"") starts with of=, so the destination becomes Tok("$dst\""). _record_command then calls _record_occ, which calls canon_operand, which calls _read_dquote. That raises Incomplete' ("unterminated double quote"), operands.py:35 does not catch it, and nothing up to main() catches it either. Result: a traceback and rc 1, where the base absorbed the error and recorded the site. The same thing happens for an unbalanced `${` in a sed side read with honour_single_quotes=False (commands.py:131), and for a lone quote that lex sees after a `#` comment inside a `$( )` body (model.py:344, verdicts_b.py:447).
Impact: this is a maintainer tool. The validate.yml step goes red, so the failure stays closed, not open, and no adopter session is affected. But a census designed to turn unparseable input into a blocking site now crashes instead, and the facade's promise of a "complete module namespace" for downstream harnesses is broken: catching ParseError around lex() misses Incomplete. The current corpus does not trigger it (there is no `dd ... of=` in scripts/), so the defect is latent.
Minimal fix: in _bind_class, return exception classes uncloned (`if issubclass(original, BaseException): return original`), or keep an original-to-clone map and swap cloned bases into `__bases__`. Add two regression tests: assert issubclass(mod.Incomplete, mod.ParseError), and run the census on a fixture containing `dd "of=$dst"`.

P2 FOLLOW-UPS
1. .claude/hooks/_lib/_cost_transcripts_parts/__init__.py:55 — the class re-binding loop rebinds every FunctionType whose `__module__` equals the component's. For a dataclass, that includes the recursive-repr wrapper on `__repr__`. The wrapper is created by dataclasses/reprlib, gets the component's `__module__` through wraps (or an explicit copy), and needs the global `_thread` (3.9-3.11) or `get_ident` (3.12+). Neither exists in the ceo-cost-transcripts.py namespace. Result: repr() and str() of UsageRecord, ScanCounters, PricingResult and Priced raise NameError. I found no production caller that formats these objects, so the damage is limited to debugging and test diagnostics. Fix: rebind only when `method.__code__.co_filename` is the component's own file, or skip dataclass-generated members.
