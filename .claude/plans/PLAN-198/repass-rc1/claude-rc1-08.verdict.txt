NEW FINDINGS (annex)

P1. The installer-census entry point splits the ParseError/Incomplete exception hierarchy.
- Where: `.claude/hooks/_lib/_installer_write_safety/__init__.py:36`.
- Cause: `_bind_class` rebuilds every package class with `type(original)(original.__name__, original.__bases__, attrs)`, keeping the original bases. In the entry point's namespace, `ParseError` becomes a fresh clone. `Incomplete` (`syntax.py:10`, `class Incomplete(ParseError)`) becomes a clone whose base is the template `syntax.ParseError`, not that clone. So in the entry point, `issubclass(Incomplete, ParseError)` is now False; in the old single-file script it was True.
- Effect: the rebound `_read_dquote` and `_read_balanced` raise the `Incomplete` clone (`syntax.py:44,50,63,75,89,93`), and every rebound `except ParseError:` stops catching it: `operands.py:35`, `commands.py:131`, `model.py:320,344,632`, `verdicts_b.py:141,440,447`. Only `syntax.py:270`, which names `Incomplete` itself, still catches it.
- Failure scenario: a scanned `scripts/**/*.sh` line such as `sort --output='a"b' in.txt`, `curl --output='x"y' "$u"` or `cp --target-directory='d"x' f`.
  1. The tokenizer accepts the line.
  2. `_classify_output_mode` (`commands.py:571`) or the writer branch (`commands.py:478`) rebuilds the canonical value `a"b` as a new token.
  3. `_record_command` → `_record_occ` → `canon_operand` → `_read_dquote` raises `Incomplete`, which its `except ParseError` no longer catches.
  4. The exception escapes `build_file_model` and `run_census` (no broad except anywhere in the package). The census dies with a traceback and exit 1, emitting no site and naming no file.
  
  The old script fell back and kept scanning. The same applies to `_expansion_refs` on a sed side holding `${x:-it's}`.
- Fail direction: still closed, because the CI gate goes red. But the instrument's own contract is broken: an input it cannot handle should become a blocking site, and it now becomes a crash.
- It also contradicts CHANGELOG.md:112 ("Entry points keep their paths and their observable contracts"), which names `check-installer-write-safety.py` at :116-117. The entry point's docstring also promises downstream harnesses the parser helpers, and `try: m.lex(t) except m.ParseError` no longer catches an unterminated quote.
- Not triggered by the current corpus: no `--opt='..."...'` form in `scripts/*.sh`. It is latent.
- Reproduction: load `.claude/scripts/check-installer-write-safety.py` with `spec_from_file_location`, then:
  - `issubclass(m.Incomplete, m.ParseError)` should print False (True before the split);
  - `m.canon_operand('a"b')` should raise (it returned before).
- Minimal fix: in `_bind_class`, return exception classes unchanged (`if issubclass(original, BaseException): return original`), or remap `__bases__` through the clones already bound in the namespace. Add tests for `issubclass(m.Incomplete, m.ParseError)` and for a census fixture containing `sort --output='a"b' x`.

P2 FOLLOW-UPS

1. Cost-transcripts dataclass `repr()` breaks.
   - Where: `.claude/hooks/_lib/_cost_transcripts_parts/__init__.py:54-56`.
   - Cause: the binder rebinds every class function whose `__module__` matches the template module. That includes the dataclass `__repr__` wrapper, which `functools.wraps` stamps with the template's `__module__`. Rebound to the entry point's globals, the wrapper's global `_thread` (`dataclasses._recursive_repr`) no longer resolves.
   - Effect: `repr()` of `UsageRecord`, `ScanCounters`, `PricingResult` or `Priced` raises `NameError`. `transcript_rollup()` returns `pricing_result` and `counters` instances to programmatic callers, so `print(rolled)`, a debugger or a pytest failure message crashes.
   - No production renderer calls repr on them today.
   - Fix: do not clone classes that have no user-defined methods, or skip functions that carry `__wrapped__`, or check `__code__.co_filename`.

2. Property getters keep the template's globals.
   - Where: `.claude/hooks/_lib/_installer_write_safety/__init__.py:29-35`.
   - Cause: `_bind_class` rebinds plain functions, staticmethods and classmethods, but not `property` objects.
   - Effect: `Site.blocking` (`report.py:32-34`) reads `BLOCKING_VERDICTS` from the template module, while `main()` reads the entry point's. Patching `m.BLOCKING_VERDICTS` changes one and not the other, which moves a test patch point.
   - Fix: rebind `fget`, `fset` and `fdel` too.

3. Stale location claims, one of them in machine-readable output.
   - `middle_out.py:22` and `summarization.py:21` still say the code "lives here in `scripts/`" (so does `compaction.py:20`, outside this payload).
   - `status.py:24` refers to "probes above".
   - The `removal_scope` strings at `status.py:70,98,133` ("this block", "the D2 block in this file") are emitted by `--probe-status` and `--json`. They now point a reader at a file that no longer holds the code.
   - Fix: name the module paths.

4. Section headers and doc comments left behind by the split.
   - `routing.py:307-321` ends with the "Programmatic API" header and the `#:` doc comment for `ROOT_ENV`, which now lives in `rollup.py`.
   - `pricing.py` and `rollup.py` end with headers for code that is in other files.
   - Cosmetic only.

5. Wrong repo-root fallback in the census engine.
   - Where: `.claude/hooks/_lib/_installer_write_safety/engine.py:115`.
   - The fallback `Path(__file__).resolve().parents[3]` is `.claude`, not the repo root, for the `hooks/_lib` layout.
