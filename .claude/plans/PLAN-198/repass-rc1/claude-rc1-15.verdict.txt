P2 FOLLOW-UPS
P2-1: decoy branches defeat the structural guard tests.
- Where: .claude/hooks/_lib/audit_emit.py:473-480.
- Scenario: the facade's emit_generic has `if action == "tool_call_lifecycle_recorded": _dispatch_generic(...)` and `if action == "settings_tamper_detected": _dispatch_generic(...)`. Both do exactly what the fall-through line does. They exist only so that inspect.getsource(audit_emit.emit_generic) still contains those comparisons, which .claude/hooks/tests/test_tool_lifecycle.py:541-563 and .claude/scripts/tests/test_ceo_boot_tamper_tripwires.py:521-525 require. The real scrub branches are generic_dispatch_04.py:62 and :159. If either is deleted or broken, those tests stay green. Today's behaviour is correct, and a regression would fall to default-deny (fields lost, not leaked), so this is test honesty, not a leak.
- Minimal fix: remove the decoys and point the tests at the real branch, either by inspecting _apply_generic_group_04 or, better, by calling audit_emit.emit_generic with a forbidden field and asserting it is dropped and the enums are coerced.

P2-2: dead duplicate action registry.
- Where: .claude/hooks/_lib/_audit_emit_parts/actions.py:7-16, with actions_core.py (234 names) and actions_extended.py (97 names).
- Scenario: these define a second 331-name _KNOWN_ACTIONS, but the install() roster does not include them (audit_emit.py:415-452). The runtime registry is the literal at audit_emit.py:45-377, which is also what _reality_ledger_parts/audit_actions.py:29-39 reads first. A maintainer who registers a new action in actions_core.py, which env-inventory.json also points at, gets no runtime effect. The action is then dropped as unknown, the same silent-drop class as the S76 skill_bootstrap_used regression.
- Minimal fix: delete actions*.py, or add a parity test pinning them equal to the facade literal.

P2-3: unknown-action breadcrumb lost repr escaping.
- Where: .claude/hooks/_lib/_audit_emit_parts/generic_dispatch_05.py:363.
- Scenario: the removed code logged f"emit_generic: unknown action {action!r}". The new code logs "unknown audit action dropped: %s" % action. An action string carrying a newline or control characters now writes raw into the audit-log.errors sidecar, which is not chained, so lines can be forged there. Callers pass constants, so exposure is low.
- Minimal fix: use %r, and keep the old message text for anyone grepping for it.
