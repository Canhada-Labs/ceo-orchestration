NEW FINDINGS (annex)

P1. .claude/hooks/_lib/_installer_write_safety/__init__.py:36 — the moved code breaks the exception hierarchy.
- Cause: _bind_class clones each package class with `type(original)(name, original.__bases__, attrs)`. The facade's Incomplete is therefore built on the ORIGINAL syntax.ParseError, not on the facade's cloned ParseError (syntax.py:6-11 defines `Incomplete(ParseError)`). In the facade, issubclass(Incomplete, ParseError) is False.
- Effect: every rebound handler `except ParseError` around a call that raises Incomplete no longer catches it. There are 8 such handlers: operands.py:35 (canon_operand), commands.py:131 (_expansion_refs), model.py:320 (extract_cmd_substs), model.py:344 (_subst_commands), model.py:632 (_token_is_expanded), and verdicts_b.py:141, 440, 447 (parse_sed_script, _sole_pipeline_producer).
- Failure scenario: a script under scripts/ contains `dd if=/dev/zero "of=$dst" bs=1 count=0`.
  - commands.py:518 builds the destination token from the raw text as `$dst"`.
  - _record_occ calls canon_operand, which calls _read_dquote, which raises Incomplete. That exception escapes operands.py:35.
  - It then escapes build_file_model and run_census, which have no handler. The census dies with a traceback, exit 1, no --json output and no --write-baseline.
  - v1.4.3-rc.1 reported a write-candidate site for the same input.
- Same failure for a substitution body that lex cannot tokenise, e.g. `$(echo a`b)`. model.py:344 used to mark the file unparseable (a blocking parse site); now the census crashes.
- Not P0: the failure is still a nonzero exit, so CI fails closed, it is maintainer-only, and no file in today's scripts/*.sh corpus triggers it (grep for `"of=` and a backtick inside `$(...)` found nothing).
- The test suite misses it: TestParseIsFailClosed (test_check_installer_write_safety.py:2189) only exercises a top-level ParseError.
- Honesty: this contradicts CHANGELOG [1.4.4] lines 112-113 ("Entry points keep their paths and their observable contracts") and the facade docstring.
- Minimal fix: in bind(), keep an original-to-clone map and build `bases = tuple(clones.get(b, b) for b in original.__bases__)`. syntax is bound before the others, so ParseError is cloned first. Alternatively, do not clone BaseException subclasses. Add a test for `issubclass(mod.Incomplete, mod.ParseError)` and a `dd "of=$x"` fixture.

  - Meanwhile `--verify-codex-pin` returns mismatch, and the pair-rail fails closed (part_01.py:587).
