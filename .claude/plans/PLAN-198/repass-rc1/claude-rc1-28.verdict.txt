F1. P2. Moved code changes exception behavior. In the facade, Incomplete is no longer a subclass of ParseError.
- Where: .claude/hooks/_lib/_installer_write_safety/__init__.py:36. The clone is built as type(original)(name, original.__bases__, attrs). syntax.py:10 defines Incomplete(ParseError).
- Cause: bind() clones ParseError into ParseError' and Incomplete into Incomplete'. Incomplete' keeps the ORIGINAL syntax.ParseError as its base, not ParseError'. Every bound function looks names up in the facade, so `raise Incomplete` raises Incomplete', and `except ParseError` catches only ParseError'. The fail-closed handlers no longer catch what _read_balanced, _read_dquote and lex raise. Affected handlers:
  - commands.py:129-133 (_expansion_refs: "An expansion we cannot delimit. Same fail-closed answer.")
  - operands.py:33-37 (canon_operand)
  - model.py:318-321, 342-345 and 630-633
  - verdicts_b.py:141, 440 and 447
  build_logical_lines still works because it catches `except Incomplete` and re-raises ParseError'.
- Failure scenario: any scanned scripts/**/*.sh containing one of these makes the census die with a traceback instead of reporting an `indeterminado` site:
  - sed 's/${//' "$f". canon gives the sed side "${", and _names_in_text then raises an uncaught Incomplete'.
  - dd if=/dev/zero "of=$dst". The dd branch builds Tok('$dst"'), and canon_operand then raises.
  The v1.4.3 code handled both fail-closed.
- Impact: the exit code is still non-zero, so the validate.yml gate still blocks and the fail direction is unchanged. But the census loses its --json report and its "report what it does not understand" contract, and crash exit 1 looks the same as drift exit 1. This instrument does not run in adopter hooks. Today's corpus does not trigger it, since CI passes.
- Minimal fix: in _bind_class, return BaseException subclasses unchanged (they have no methods that use globals), or rebuild bases through a map from original to clone. Add a test, run through the entry point, that asserts issubclass(Incomplete, ParseError) and checks that the sed 's/${//' fixture produces an indeterminate site.

F2. P2 (honesty, diagnostic fails open). check-substrate-drift.py reports an installed Codex older than the pinned one as "compatible".
- Where: .claude/scripts/check-substrate-drift.py:571-578.
- Cause: the new branch tests in_range(installed, pin["range"]). The shipped .claude/governance/codex-cli-pin.txt:199 reads ">=0.128.0". The pair-rail's compatible route uses the code constant 0.160.0 and also requires a version strictly newer than the manifest.
- Failure scenario: an installed codex 0.150.0 against the 0.160.0 pin now gets CODEX_INSTALLED_COMPATIBLE at severity "info", with the message "meets the unbounded semantic floor >=0.128.0 ... the payload hash is verified separately", and no restore advice. `--strict` (line 1278) now exits 0. Meanwhile check_pair_rail --verify-codex-pin returns mismatch/payload_sha256_mismatch, and the rail fails CLOSED at the next L3+ call. That is exactly what the CODEX_INSTALLED_NOT_PINNED finding this branch replaced used to predict. The older-than-pin restore branch (lines 583-587) is now unreachable for 0.128.0 up to 0.159.x.
- Context: the Known-open entry declares the pin-file vs ADR-182 floor disagreement, but not this effect on the diagnostic. No automated gate consumes this script, and installs do not receive .claude/governance/.
- Minimal fix: require compare_semver(installed, max(pin floor, cli_currency.CODEX_VERSION_FLOOR)) >= 0 AND installed > pinned (the same test as compatible_package_version).
