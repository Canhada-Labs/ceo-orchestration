P2 FOLLOW-UPS
1. P2 — .claude/scripts/audit-verify-chain.py:588-591. The strict counter check reads only the first 64 bytes. A counter file of "5" followed by 63+ bytes of whitespace and then trailing garbage is accepted as 5, although the docstring says a counter that is "not plain decimal digits" exits rc 3. The writer never produces this. Minimal fix: read 65 bytes and fail if more than 64 come back, or read the whole regular file with a size cap.
2. P2 — audit-verify-chain.py:579-587 versus :617-626 and CHANGELOG.md:305. When permissions refuse the lstat of the counter (parent directory not searchable), the result is rc 3 chain_length_unreadable. The same refusal on the log falls through to the open and gives rc 4. The docstring promises rc 4 "when the read is refused by permissions", while the CHANGELOG just says "unreadable counter exits 3". Minimal fix: map PermissionError from lstat to EXIT_PERM in _expected_length_strict and make the CHANGELOG line say "3 (4 when refused by permissions)".
3. P2 — audit-verify-chain.py:642-655. In strict mode with stdin, stream.close() also closes sys.stdin.buffer. An in-process caller of main([...,'--stdin','--strict-against-counter']) loses stdin afterwards; the CLI itself is unaffected. Minimal fix: call stream.detach() instead of close() when log_path is None.
4. P2 — .claude/scripts/caller_repo_guard.py:52-53. The scrub removes only GIT_DIR and GIT_WORK_TREE, but the comment says no repo-redirecting environment may decide the answer. GIT_COMMON_DIR, GIT_OBJECT_DIRECTORY, GIT_INDEX_FILE and GIT_NAMESPACE still pass through, so a harness run from inside a git hook could fingerprint the wrong refs. This is a maintainer tool, inert on installs. Minimal fix: drop every variable in `git rev-parse --local-env-vars`, or every GIT_* except an allowlist.
5. P2 — .claude/hooks/_lib/_budget_summary_parts/*.py and _audit_query/queries.py:330. The extracted modules resolve names only through the facade's globals: the parts have no imports, and cmd_errors calls the facade-only default_errors_path. Importing and calling them directly raises NameError, while condition 7 tells hand-patchers to patch "the module". Patching the file works through the facade. Minimal fix: a one-line header in each part saying it is facade-bound and must not be called directly. Optionally add an __init__.py to _budget_summary_parts for parity with _audit_query.
