P2 FOLLOW-UPS

P2-1. The secret scan on SKILL.md files only looks at the first ~117 characters (pre-existing).
- Where: .claude/hooks/_lib/agent_spawn/skill_reference.py:250-251 and prompt_rules.py:112-128.
- Cause: _skill_ref_validate_hash_and_redact calls _redact.redact_secrets(text) with the default max_chars=120 (_lib/redact.py:117, 120, 186-194). The output is collapsed to one line and cut to 117 characters plus "...". The token check at :251 therefore only sees the first ~117 characters of SKILL.md, which is the frontmatter.
- Two more gaps:
  - redact_secrets truncates its input at 64 KiB (redact.py:108, 144-146), while reference files may be up to 1 MiB;
  - the [AWS_SECRET] token emitted by redact.py:102 is missing from _SECRET_TOKENS_IN_OUTPUT.
- Failure scenario: a SKILL.md with a credential anywhere in its body passes sub-check 11, and a reference-mode sub-agent loads it into its context. ADR-051 sub-check 11 and docs/threat-model.md:1884 present this check as the mitigation for "Secret leak embedded in SKILL.md". The existing test (tests/test_check_agent_spawn_skill_reference.py:229-263) puts the key right after a ~50-character frontmatter, inside the window, so it cannot catch this.
- Not a regression of this delta: the code is identical in the old single file.
- Rated P2, not P1: the file is already committed and protected as a canonical file, and the default inline SKILL CONTENT path has no scan at all. Raise it to P1 if the Owner treats threat-model row 10 as load-bearing.
- Minimal fix:
  - call redact_secrets(text, max_chars=0) over 64 KiB chunks, or use a scan API that does not truncate;
  - add "[AWS_SECRET]" to the token set;
  - add tests with the key placed after character 200 and after 64 KiB.
