FINDINGS

P2-1 — .claude/hooks/_lib/_ceo_boot_parts/harness_governance.py:304 (_sentinel_patterns)
Failure scenario: _sentinel_patterns() reads the _PATTERNS list by parsing .claude/hooks/check_canonical_edit.py. The PLAN-197 split in this same release moved that list into .claude/hooks/_lib/canonical_edit/paths.py:238, inside _find_sentinels. check_canonical_edit.py no longer has any _PATTERNS assignment. So every run, in the dogfood repo and in every install, returns derived=False:
- sentinels_pending_gpg scans only the 4 fallback patterns.
- It drops six of the guard's ten patterns: architect/wave-0a, wave-0b, wave-1-2, wave-minus-1, staging/review and audit-v2/architect/round-*.
- Its summary always ends with "[padrões em FALLBACK — a autoridade não foi lida]".
This is advisory and the summary flags the fallback, so gate_pass is unaffected. The patterns it loses are mostly old grandfathered ones. But the "derived from the authority" rule from S321 is broken, and the digest shows a permanent warning. No test covers _sentinel_patterns.
Minimal fix: parse _lib/canonical_edit/paths.py as well, or instead (try the entry point first, then the module). Add a test asserting derived=True on the real tree.

P2-2 — .claude/scripts/ceo-boot.py:120-178 (dead copy of check_tier_a_spec_version_drift)
Failure scenario: the entry point defines this function again after install(). The copy actually registered in TIER_A_CHECKS is the one at model_persona.py:6 (bound at scheduled_cache.py:376). The module attribute ceo_boot.check_tier_a_spec_version_drift therefore points to a copy the dispatcher never runs. The two bodies are identical today, so runtime behavior is unchanged. But:
- test_check_vacuous_checks.py extracts this function from the entry point's text with ast, so the S287 regression guard now tests the dead copy. Reverting the cure in model_persona.py would leave it passing.
- A maintainer who edits the function they see in ceo-boot.py changes nothing at runtime, and the tests still pass.
- The new docstring, "Lesson validation remains delegated to `_validate_boot_lesson`", has nothing to do with this check. It exists only so test_dead_symbol_lesson_render_safe_is_gone finds that string.
Minimal fix: delete the copy in the entry point, and have the tests load the function from the module (or from the part file).

P2-3 — .claude/scripts/check-vacuous-checks.py:133 and ceo-boot.py:180-184 (guards that now check text, not code)
Failure scenario:

P2-4 — .claude/hooks/_lib/_ceo_boot_parts/harness_governance.py:174 onward (check_hook_live_smoke coverage shrank)

P2-5 — .claude/hooks/_lib/_ceo_boot_parts/*.py:1 (__doc__ overwritten)

Minimal fix: drop the part docstrings, or save and restore __doc__ around install().

P2-6 — .claude/hooks/_lib/_ceo_boot_parts/model_persona.py:215 (new main_checkout_state check)
It can make up to three git calls of 0.8 s each, one after another, inside the 5 s overall budget. It has no entry in PER_CHECK_TIMEOUT_OVERRIDES_S. If the overall budget runs out, a check gets status "timeout", which turns gate_pass false. In installs where origin/HEAD is unset and the default branch is not "main", the check is permanently yellow; the CHANGELOG declares that.
Minimal fix: add an override entry, and run the symbolic-ref calls only when they are needed.
