### 1. P1 annex — APPROVE trailer matching accepts attacker-controlled prefixes

**FILE:LINE:** [templates/codex/pre-push-review-gate.sh:169](</private/var/folders/9n/hm9srl0s1nz45_p12tj61pd80000gn/T/repass-ga.nb1a8y/wt/templates/codex/pre-push-review-gate.sh:169>), [templates/grok/pre-push-review-gate.sh:266](</private/var/folders/9n/hm9srl0s1nz45_p12tj61pd80000gn/T/repass-ga.nb1a8y/wt/templates/grok/pre-push-review-gate.sh:266>)

**Concrete failure scenario:** Both gates run:

```sh
grep -Eiq '^Pair-Rail-Reviewed:[[:space:]]*APPROVE'
```

This accepts `Pair-Rail-Reviewed: APPROVED`, `Pair-Rail-Reviewed: APPROVE-WITHOUT-REVIEW`, mixed-case variants, and matching message-body lines. A canonical commit containing such text is treated as reviewed and clears the Grok enforcement gate without an exact `APPROVE` verdict. Direct probes confirmed all those prefixes are accepted.

**Minimal fix:** Parse the trailer block with `git interpret-trailers --parse`; require exactly one case-sensitive `Pair-Rail-Reviewed` value equal to `APPROVE`, and reject duplicate or conflicting values. Add negative tests for prefixes, body lines, case changes and duplicate trailers.

This does not falsify condition 26—Codex’s template is already declared a reminder rather than a security gate—or condition 82, which excludes Grok upgrades in this release. It remains a published-template P1.

### 2. P1 annex — merge commits can carry canonical changes without review

**FILE:LINE:** [templates/codex/pre-push-review-gate.sh:161](</private/var/folders/9n/hm9srl0s1nz45_p12tj61pd80000gn/T/repass-ga.nb1a8y/wt/templates/codex/pre-push-review-gate.sh:161>), [templates/grok/pre-push-review-gate.sh:225](</private/var/folders/9n/hm9srl0s1nz45_p12tj61pd80000gn/T/repass-ga.nb1a8y/wt/templates/grok/pre-push-review-gate.sh:225>), [templates/grok/pre-push-review-gate.sh:334](</private/var/folders/9n/hm9srl0s1nz45_p12tj61pd80000gn/T/repass-ga.nb1a8y/wt/templates/grok/pre-push-review-gate.sh:334>)

**Concrete failure scenario:** The diff adds `--root` to cure root-commit blindness but still calls `git diff-tree` without `-m`, `-c` or `--cc`. Plain `diff-tree` emits no paths for merge commits. If both parents are already remote-reachable and the new merge resolution changes a canonical file, the range can contain only that merge; both the aggregate classifier and per-commit check see zero canonical paths and allow the push without review.

Measured against two merge commits in this candidate:

- `d2d46f…`: plain command returned 0 paths; `-m` returned 121.
- `120b70…`: plain command returned 0 paths; `-m` returned 3,286.

**Minimal fix:** Enumerate merge diffs explicitly—safest minimal change is `git diff-tree -m --root ...` at every collector, followed by deduplication—and add a regression where a merge-only conflict resolution changes a canonical file.
