# Consensus — PLAN-190 W1, round 1

> Scope of this verdict: **design-coherent** (PLAN-134 W1). It certifies the design is internally
> coherent across the forced perspectives; it does NOT authorize shipping. Shipping is authorized only
> by the verification cascade: V0 plan-check → V1 deterministic gates → V2 Codex pair-rail (the sole
> LLM truth gate, fail-closed to the Owner) → V3 Owner GPG.

## Consensus findings (2+ critics, all also raised by Rail-1 unless noted) — ALL applied in v2/v3

1. **Manifest must be on disk BEFORE anything slow** (A, B, C, Rail-1). v1 ran `git rev-parse` (3 s)
   + `git status` (5 s) before writing, inside a hook with a 5 s timeout — the record could vanish in
   exactly the recovery scenario. **Applied:** manifest + script snapshot written first; git
   enrichment after, `--no-optional-locks`, total budget 1.2 s, unknown on failure; test with a fake
   4 s `git` proves the manifest exists and the hook returns early.
2. **Block reason counts-only** (A, B, C). Arg key names in the reason reopen the instruction-adjacent
   channel PLAN-179 closed by removal; the run id must be validated before it is echoed. **Applied:**
   reason carries counts (changed / only-recorded / only-now / script differs) and the two routes; the
   key list lives in the manifest; `resumeFromRunId` validated by shape, an unrecognised value is
   recorded (`resume_id_unrecognised`) and never echoed; adversarial-key test.
3. **Binding never guesses** (A, B, C, Rail-1). "Latest unbound" bound the run to the wrong manifest
   when the launch was not recorded, producing a false block or a false match. **Applied:** with
   `tool_use_id` → bind only on exact match, else `orphan`; without → bind only when EXACTLY ONE
   unbound launch exists in the session, else `orphan`; never across sessions; `bind_method` recorded;
   a mismatch against a heuristically bound manifest is advisory, never a block (C).
4. **Guard split: args block, script advisory** (A, C; B wanted enforce with a rollback switch — both
   satisfied). The substrate sanctions resuming over an edited script (only changed prefixes
   re-execute); the demonstrated loss is `args`. **Applied:** args mismatch ⇒ block; script mismatch with
   same args ⇒ `systemMessage` advisory (`CEO_WORKFLOW_SCRIPT_GUARD=enforce` to block);
   `CEO_WORKFLOW_RESUME_GUARD=0` = advisory mode keeping the ledger (B's rollback button, separate from
   the kill-switch).
5. **`relaunch` must be exact for inline scripts** (A, C, Rail-1). v1 stored only the hash and pointed
   at the harness JSON, which exists only after the run ENDS. **Applied:** the effective script bytes
   are snapshotted (0600) before dispatch; `relaunch` prints the snapshot path (pass it as `scriptPath`)
   and whether the original file changed; the harness-persisted path, when visible in the response, is
   recorded with `persisted_matches_snapshot`.
6. **Corpus gates red in v1** (A, B, C, Rail-1): bare `unittest.TestCase` in `tests/unit`; counts
   59/48/50/71 cited in 10 docs; `test_template_dogfood_parity.py` pins 50/47; the generated
   `docs/COMMAND-SKILL-HOOK-MAP.md`; `env-inventory.json`. **Applied:** `TestEnvContext`; `bump-counts.py`
   (same regexes as `verify-counts.sh`) over 10 docs; pins 52/49 with the relationship 52 == 49 + 1 + 2;
   map and env inventory regenerated by their own generators; CHANGELOG `[Unreleased]` entry.
7. **Distribution precondition declared** (A, B, C). `upgrade.sh` merges registrations per RECORDED
   ceremony; a target with no recorded ceremony receives no hooks. **Applied:** declared in
   `docs/workflow-recovery.md`; W6 tests both legs; `check_workflow_launch.py` named in the user
   profile's `_derivation.blocking_inclusions` with its route (C).

## Single-agent insights KEPT

- **Override route usable in session** (C; B's R-DEV9 and "unseen 5" describe the loop risk the same
  way): the env override is invisible to whoever reads the block. **Applied:** `ceo-launches.py force
  <run> --reason …` writes a one-shot token; the next resume proceeds, is recorded `mismatch_forced`
  with the reason and announced; `report` exposes the forced ratio (the stop rule's metric). A's
  concern (the model must not self-unblock silently) is met by visibility + reason + one-shot, not by
  prevention — the guard is a recovery instrument, not a security matcher.
- **Inconclusive is a third state** (Rail-1): an unavailable hash is neither a block nor a match.
  **Applied.**
- **No truncation of args** (Rail-1; C nice-to-have): the hash is over the full canonical JSON.
  **Applied.**
- **Rebind must invalidate the previous association** (Rail-1). **Applied** (`unbind` line; lookup
  verifies the manifest still carries the run).
- **Event without `hook_event_name` but with `tool_response` is a Post** (C). **Applied.**
- **The tool is asynchronous, not synchronous** — C's CRITICAL R-VP1 ("the run id only arrives when
  the run ends") was checked against 281 real `tool_use → tool_result` pairs in a consumer's own
  transcripts: the response arrives 0.3 s after the call ("Workflow launched in background. Task ID …").
  The binding-at-launch design stands; the check is recorded here as evidence, not accepted as a
  finding.

## Single-agent insights REJECTED or DEFERRED

- **Compare the code revision in the guard** (raised as OQ-3; all three critics agree NOT to): record
  only — W2's checkpoint binds phases to revisions. Rejected for W1.
- **Bind via the harness script artifact instead of the response** (C): the response already carries
  the id at launch (see above); the persisted path is recorded when visible. Deferred: no separate
  binding channel.
- **Audit event for `workflow_launch_recorded` / `workflow_resume_blocked`** (A, B, C all want it named):
  registering an action is the audit owner's ceremony (`_KNOWN_ACTIONS` + SPEC). Deferred to
  `PLAN-190-FOLLOWUP-audit-actions` (to be filed before the SIGN).
- **`PostToolUseFailure` registration to mark failed launches** (B): deferred (W6, with the
  distribution tests).
- **Retention / `gc --keep-days`, `reindex`, redacting arg values in `show`** (A, B, C nice-to-have):
  deferred, documented as limitations.
- **Timeout 10 s on the registrations** (C): not needed after write-first with a 1.2 s git budget; the
  5 s registration stays (the hook's slow path is now bounded).

## Round verdict: PROCEED (design-coherent)

All three critics returned ADJUST with must-fixes that overlap almost entirely with each other and
with Rail-1; every must-fix is implemented in v3 with a regression test, and the corpus gates that
were red in v1 are green in the shadow (70+ tests, parity, generated docs, counts, hygiene,
contamination, env inventory). No critic asked for a different architecture. A second debate round
would re-judge text, not design; the revised BYTES go to Rail-2 (fresh, cold) and then to the Owner.
