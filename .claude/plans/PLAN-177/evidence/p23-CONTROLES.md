## P1-2 — a versão que ninguém vigiava

### C1 — versão hardcoded volta a `npm/INTEGRITY.md` (superfície 1)

Gate: `test_npm_docs_carry_no_bare_version_literal`

```
E  AssertionError: bare version literal in an npm doc (VERSION is the only authority;
   make the prose version-neutral):
E    npm/INTEGRITY.md:4: > is currently 1.0.1; the authority is: `VERSION` at the repo
     root is the single (1.0.1)
1 failed in 0.15s
```

É literalmente o P1-2 do `verdict-ga-1` (`npm/INTEGRITY.md:4`, "currently
1.0.1"): com o gate no lugar, o defeito original **não passa**.

### C1b — versão nua em `npm/README.md` (superfície 2)

```
E  AssertionError: bare version literal in an npm doc …
E    npm/README.md:1: # ceo-orchestration 1.0.1 (1.0.1)
1 failed in 0.12s
```

As duas superfícies são provadas separadamente porque `SCAN_ROOTS` lista
**arquivos** (CF-5), não a pasta `npm/`: cobrir uma não implica cobrir a outra.
A linha de stamp (`last-reviewed: … v1.3.0`) permanece isenta em ambas —
provado pelo controle hermético embutido, que roda em toda execução verde e
exige exatamente 1 offender por superfície com o stamp presente no mesmo
arquivo.
