+WHY THIS EXISTS
+---------------

+``working-directory: .claude/scripts``. The "Emit step summary" step read it

+``FileNotFoundError`` — swallowed by ``2>/dev/null || echo "N/A"``. The summary
+reported ``Projection: N/A`` on fully green runs and nobody could tell that
+apart from a real absence. Adding ``working-directory`` to that step is the
+fix; this test is the control that keeps it, and that would have caught the
+original bug.
+
+The assertion is STRUCTURAL, not a substring count: a step "carries" the
+working-directory only if the key belongs to THAT step's own mapping. A
+``grep -c working-directory`` would pass with the key attached to the wrong
+step. Parsing is stdlib-only and deliberately does not ``import yaml`` — a
+gate that ``skipTest``s itself when an optional dependency is missing is a gate

+def _split_steps(text: str) -> List[Tuple[str, List[str]]]:
+    """Return ``(step_name, body_lines)`` for every ``- name:`` step.
+
+    A step runs from its ``- name:`` line until the next ``- name:`` at the
+    same or shallower indent, or until the first non-blank line indented LESS
+    than the dash (which ends the enclosing ``steps:`` list).
+    """

+    starts = [i for i, ln in enumerate(lines) if _STEP_RE.match(ln)]

+    for pos, start in enumerate(starts):

+        end = len(lines)

+                break

+leaked() {  # $1 = target
+  ( cd "$1" && git status --porcelain -uall 2>/dev/null ) \

+# `<source>:<line>:<pattern>\t<path>`, so the source file is checkable.
+ignoring_rule() {  # $1 = target, $2 = relpath
