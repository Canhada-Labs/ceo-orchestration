# WHY THE INDIRECTION EXISTS
# --------------------------
# `.claude/settings.json` denies `Edit(SPEC/**)`, and on the current CLIs
# that deny covers every file-editing tool. The glob matches ANY path
# containing a `SPEC/` segment — including a staged copy inside a plan
# directory — so a pack file could not be authored at
# `staged-w01/SPEC/v1/audit-log.schema.md` at all.
#
# That deny is CORRECT and is not to be worked around: SPEC/v1 is a
# canonical governance surface, and the ONLY writer to it is the Owner's
# signed canonical-edit ceremony (ADR-031). The honest route is therefore
# to name the artifact for what it is — a pack payload, not a SPEC file
# — and let the land script perform the copy under the Owner's
# signature, at which point the sentinel scope covers the write.
#
# CONTRACT FOR THE LAND SCRIPT
# ----------------------------
# - The payload is the COMPLETE destination file (live content + the
#   PLAN-179 edits already applied), byte-for-byte what must end up at the
#   destination. It is NOT a diff and NOT an excerpt: `cp`, never `patch`.
# - The destination path MUST appear in the signed sentinel's Scope, or the
#   canonical-edit guard blocks the write — which is the desired
#   behaviour, not an obstacle to route around.
# - `staged-w01/SPEC/v1/audit-log.schema.md` still exists in this pack as
#   the untouched BASE copy (sha256
#   fdb5447db3f4c70b3cbc28524afd0c4ea7a54504bb9ffbd7cf8646ecb75d5f42,
#   byte-identical to live at staging time). It is evidence for the
#   pre-land drift check, NOT a land input. If live has moved off that
#   hash, this artifact was rendered against a stale base — re-render
#   it, do not land it.
