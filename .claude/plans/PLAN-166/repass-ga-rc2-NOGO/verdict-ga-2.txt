1. **P1 — fix before GA**  
   **FILE:LINE:** `.github/workflows/npm-publish.yml:61`, `.github/workflows/npm-publish.yml:216`, `.github/workflows/npm-publish.yml:221`, `.github/workflows/npm-publish.yml:408`, `.github/workflows/npm-publish.yml:427`  
   **Concrete failure scenario:** Push `v1.3.0` at commit A; its gate succeeds and the publish job waits for approval or later fails. The tag is then deleted and recreated at corrective commit B, as the workflow’s own recovery comments prescribe. The old job can still be approved, or its failed portion rerun, using the original event SHA A. Its previously successful `await-release-gate` need not rerun, checkout remains pinned to A, and all version checks still pass because both trees say `1.3.0`. With the registry version still absent, it publishes A irreversibly even though the live tag points to B. Nothing immediately before `npm publish` verifies the current remote tag still resolves to `GITHUB_SHA`.  
   **Minimal fix:** In the publish step, after environment approval and immediately before `npm publish`, resolve and peel the current remote tag fail-closed and require it to equal `GITHUB_SHA`. Add a regression test covering delete/re-tag plus an obsolete pending/rerun workflow.

2. **P2 — follow-up**  
   **FILE:LINE:** `.claude/scripts/local/verify-counts.sh:35`, `.claude/scripts/local/verify-counts.sh:43`, `.claude/scripts/local/verify-counts.sh:45`, `.claude/scripts/local/verify-counts.sh:175`  
   **Concrete failure scenario:** The expanded `--help` contract advertises exact counts of 188 ADRs, 29 release steps, and 21 workflows. At this tag, disk contains 190 ADRs, 31 named release steps, and 22 workflows. The executable derives the live values for checking documents but never checks its own user-visible help text, so the gate reports clean while publishing stale exact claims about itself.  
   **Minimal fix:** Remove current-value parentheticals from the static contract or generate them from the derived values. Add a self-liveness test so `--help` cannot carry unverified exact inventory counts.

3. **P2 — follow-up**  
   **FILE:LINE:** `.claude/scripts/await_release_gate.py:174`, `.claude/scripts/await_release_gate.py:261`, `.claude/scripts/await_release_gate.py:351`  
   **Concrete failure scenario:** `parse_timestamp()` accepts out-of-range components because `calendar.timegm()` normalizes them. A matching candidate with `created_at: "2026-08-01T99:99:99Z"` and a successful `release-gate` produced `GRANT` in a direct evaluation. That contradicts the stated fail-closed-on-malformed-input contract and can turn malformed timing evidence into a fresh candidate.  
   **Minimal fix:** Validate hour, minute, second, and UTC-offset ranges before conversion—prefer constructing a stdlib `datetime`—and add negative tests for normalized overflow and implausible future timestamps.
