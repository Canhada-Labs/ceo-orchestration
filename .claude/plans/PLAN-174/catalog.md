## 0. Post-mortem: por que o mandato existente falhou (F1 do consenso)

`docs/OWNER-CEREMONY-CONTRACT.md:167-180` exige desde S81: *"new
ceremony scripts MUST be generated by that tool"* — o tool existe
(`.claude/scripts/local/generate-ceremony.sh`, 558 linhas; a doc diz
440, stale em 118).

**Sonda de conformidade (S316, por comando):**
```
python3: glob .claude/plans/*/OWNER-*.sh + owner-*.sh  → 16 arquivos
         ~/canhada-labs/OWNER-*.sh                     → 9 arquivos
         marca "AUTO-GENERATED" em qualquer um deles   → 0 de 25
```
(Os críticos B e A mediram 0/27 com um corpus ligeiramente maior — as
duas cópias de `scripts/local/historical/`; o resultado é o mesmo:
**conformidade ZERO**, sem nenhum instrumento notando, através de ≥8
planos.)

**Causa (verificada no gerador):** a guarda G1 do
`generate-ceremony.sh` exige que cada `--canonical-paths` case com
`_CANONICAL_GUARDS` — o gerador foi construído para **cerimônia de
canonical-edit com sentinel**, não para **corte de tag/publish**. As
duas famílias têm shapes diferentes (canonical-edit: sentinel GPG +
scope; corte: tag/gh release/npm + retomada). O MUST falhou porque
mandava usar uma ferramenta que não emite a família que os trens
precisavam — e nenhum check de proveniência existia para acusar o gap.

**Consequências normativas:**
1. O catálogo separa as DUAS famílias (abaixo).
2. A primeira regra do lint W2 é o **check de proveniência** que o
   contrato sempre pediu e nunca teve (`:178-180`).
3. O W3 tem escopo real: estender o gerador à família de corte.

## 5. Disciplina de erro — DRAFT de ADR (deliverable vii; formaliza no closeout)

> O ADR formal (`ADR-195`) entra na janela de closeout — adicionar ADR
> muda contagens derivadas em `CLAUDE.md`, que é cache-stable
> mid-session. O conteúdo decidido:

- **Decisão:** cerimônia usa `set -u -o pipefail` **sem `-e`** (a
  família com `-e` produziu o P0 do round 28 — `_grv_rc=$?`
  inalcançável; a família sem `-e` produziu os fail-open dos rounds
  6/7/13/19/25 por FALTA do idioma abaixo — o problema não era a
  ausência de `-e`, era rc não checado).
- **Idioma obrigatório para rc esperado-não-zero:**
  `if cmd; then …; else rc=$?; …; fi` — nunca `cmd || true`, nunca
  `set +e` sem restore imediato na linha seguinte.
- **Todo rc de comando que toca estado remoto irreversível é checado
  EXPLICITAMENTE** na linha seguinte à invocação.
- O lint W2 enforça o idioma (regra A2); sem esta decisão as regras
  "`|| true`" e "rc engolido" seriam incoerentes entre si.

## 6. Decisões de escopo registradas

- **Não-templatização:** o lint de cerimônia NÃO é entregue a adopters
  (cerimônia com pinentry/dois-rails é superfície DESTE projeto) —
  registrado para o PLAN-183 não herdá-lo por engano.
- **Wire de CI:** job próprio em arquivo NOVO (`ceremony-lint.yml`),
  NÃO-templatizado (decisão do CEO registrada no consenso, divergência
  de Critic-C anotada com herdeiro = abertura do 183-W2);
  `validate.yml` intocado até o PLAN-183 W2 fixar o ramo do drift-gate
  (a extensão do `find` é o passo de migração pós-183-W2).
- **CI é O GATE; a perna local é git hook clássico opt-in, entregue
  (instalador + doc), bypassável declarado** — nunca contada como
  camada de enforcement.
- **Escape hatch (forma fixada):** `CEO_CEREMONY_LINT_UNLOCK=<sha256 do
  arquivo>` + `CEO_CEREMONY_LINT_UNLOCK_REASON` obrigatório, ambos no
  audit trail; unlock sem motivo = bloqueio mantido (padrão ADR-186).
- **Descoberta por conteúdo** com controle positivo: a classe A3 TEM de
  ser achada nos 4 `run-*.sh` — se o lint der verde neles, o escopo
  está errado (o gate falha).
