# Codex CLI binary SHA-256 pin — RETIRED (PLAN-163 T5.2 / ADR-182)
#
# This file is a TOMBSTONE. It intentionally carries NO pin hex.
#
# Why retired: the hex this file used to carry was computed via
# `shasum -a 256 $(which codex)`, which follows the npm symlink to the
# JS *launcher* (`@openai/codex/bin/codex.js`) — NOT the native Rust
# payload that actually executes. The launcher is version-stable, so
# the 0.144.1 -> 0.144.6 payload bump passed the "pin" without any gate
# trip (PLAN-163 T5.2a evidence,
# `.claude/plans/PLAN-163/probes/payload-sha-evidence.md`). The pin
# attested the wrong artifact.
#
# Replacement: `.claude/governance/codex-cli-pin-manifest.json`
# (ADR-182 — codex payload pin + verify-then-invoke enforcement).
# The manifest pins the sha256 of the NATIVE payload per targetTriple,
# and `check_pair_rail.py` verifies the payload it is about to execute
# against that entry at every invocation (verify-then-invoke).
#
# Pin update ceremony: see ADR-182 §Ceremony (per-triple payload sha,
# npm dist.integrity provenance, sentinel-gated edit of the manifest).
#
# This tombstone stays on disk (and stays kernel/canonical-guarded) so
# that (a) historical verdict files that declared
# `tool_versions.codex_cli_binary_sha256` keep a resolvable referent,
# and (b) a revived launcher-hash "pin" cannot be silently reintroduced
# at this path. `validate-pair-rail-verdict.py` treats an empty
# (comment-only) pin file as "no launcher pin" and enforces the
# manifest-based payload pin instead.
